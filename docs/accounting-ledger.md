# 仕訳帳の初期基盤

`accounting_accounts`（申告主体ごとの勘定科目）、`accounting_entries`（仕訳の表題と日付）、`accounting_lines`（借方・貸方）を追加した。申告主体・業態の有効期間、店舗の所属期間、科目の申告主体一致を検証してから仕訳を確定する。借方・貸方が一致しない仕訳や0円の仕訳は確定できない。確定した仕訳と明細は直接変更・削除できない。

`accounting_trial_balance` は確定仕訳だけを指定期間・申告主体で集計する。データベースのテーブルと関数はブラウザから直接操作できない権限にしてある。今は申告者の本人情報と開始残高が未確認なので、実際の注文・領収書・請求書は自動転記しない。仕訳帳を作っただけで税務申告に使える状態とは表示しない。

`accounting_source_links` は日次締めと登録経費から仕訳への対応を1件ずつ保存し、同じ元データの二重紐付けを拒否する。元データの店舗・日付・金額の一致を作成時に検証する。請求書と経費は同じ取引の可能性があるため、請求書そのものを自動仕訳の元データに加えない。`accounting-sources-api` と「仕訳の元データ確認」画面は月ごとの候補と証憑・税区分を読み取り専用で表示する。元データに後日変更があれば金額・日付の差を警告するが、削除・取消された元データや銀行入金との突合はまだ必要である。

同じ確認画面に、日次締めの現金予定額・実在高・差額とPayPay/その他のPOS売上を表示する。差額0円はレジ内現金の一致だけを意味する。決済サービスの振込額や銀行明細とは照合していないため、入金照合済みと表示しない。

誤った確定仕訳は `reverse_accounting_entry` で反対仕訳を作り、理由・実行者・元仕訳との関係を残す。元仕訳と反対仕訳は両方とも直接書き換えられない。まだ操作画面はなく、内部処理用の機能である。

次に必要なのは、申告主体の本人確認と開始残高、領収書・売上・入金の二重計上防止、取引ごとの仕訳ルール、税率・棚卸・固定資産の処理、訂正の承認履歴、銀行・現金の照合。試算表から損益計算書・貸借対照表を作る前に、期首残高と年度締めも整える。
