# 毎日の証憑登録と請求書の支払管理

## 日々の流れ

- スタッフ・厨房・店長がスマホでレシートまたは請求書を撮影する。端末上の日本語 OCR は任意で、失敗しても写真を登録できる。写真は店舗別に非公開 Storage に保存し、API がその店舗の権限を確認して 60 秒の閲覧 URL を発行する。
- 同一写真は SHA-256 でブロックし、同日・同額・同じ取引先の候補を登録直後に伝える。店長ホームは翌日以降の未確認レシート、請求書の未払残高、期限超過を表示する。レシート画面は古い未確認から並べる。
- OCR の結果は下書きにすぎない。店長が原本を見て日付、税込額、取引先、費目、税区分を確定すると経費集計に反映する。食材・商品の仕入れが疑われるものは一般経費への確定を止め、理由つきで区別して保管する。棚卸や原価への自動連携は未実装。
- 経費の月次締めは月末後、未確認写真と税区分未設定がなくなったときに行う。締めた月の経費変更は禁止し、監査記録と税込合計を保持する。売上、給与、棚卸を含む決算の締めではない。
- 業者請求書は下書き → 確定・未払い → 一部または全額支払い。支払日、金額、方法、照会番号を追記し、残高と期限超過を見られる。支払い記録は冪等キーで二重登録を防ぐ。請求日基準の請求額、前月比、売上比、取引先上位を参考表示する。請求書を撮影しただけでは経費や現金支出へ計上しない。

## 導入順と前提

1. `20261003033000_financial_reporting_foundation.sql`、`20261003043000_receipt_capture.sql`、`20261003053000_supplier_invoices.sql` の順に適用する。
2. `receipt-api` と `invoice-api` を配置し、画面のアクセス権を実データで確認する。非公開 `expense-receipts` バケットはレシートの migration が作成する。
3. ブラウザの日本語 OCR は Tesseract.js 5.1.1 CDN を要求する。通信や端末処理が遅いときは OCR を省略して写真を提出できる。
4. 売上との比率は税込で請求日基準。買掛金、仕入、消費税、銀行明細、電子帳簿保存法の要件を網羅した仕訳や申告書にはまだなっていない。会計利用前に法人名・事業者情報、科目、証憑保存要件、二重計上を検証する。
