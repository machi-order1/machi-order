# MACHI ORDER：経営分析の実装順

店舗スタッフのトップには完成・検証済みで、当日の仕事に必要な機能だけを表示する。
将来機能はこの開発リストと店長・オーナー向け分析画面で管理し、未完成のボタンは置かない。
数字の分母・除外条件・データ欠損の表示を先に決め、経営判断に誤解を作らない。

## 第1段階：販売構成（PR #61）

- 店舗別の3か月・半年・1年・記録開始からの会計済み売上と昼夜内訳。
- 博多系／えび塩系、個別商品、麺量、A〜Eセット、チャーシュー丼単品・セットの実績。
- 未会計・取消は除く。麺量未選択は「未記録」、システム導入前は「記録なし」。
- セット付帯率＝油そばを含む注文のうち同じ注文にセットがある割合。杯数の割合とは別。
- 商品別売上の明細金額は注文全体の値引きを配賦していない。

## 第2段階：仕込み・補充予測

1. レシピマスター：商品・サイズ・セットの構成要素ごとにチャーシュー枚数、麺玉数、米量などを登録。変更履歴と適用日を保存する。
2. 在庫：棚卸の実数、仕込み済み、発注済み、廃棄、スタッフ消費を別々に記録。未棚卸なら「予測不可」と表示する。
3. 需要：曜日×昼夜×直近の販売数を使い、最低限の平均・上振れ・季節変動を提示。少量データは予測を確定値にしない。
4. 補充：予想必要数＝営業予定日に販売見込みの各商品数×レシピ使用量＋安全在庫。現在庫と入荷予定を引き、発注リードタイムから「不足しそうな日」を示す。
5. 3・4店舗目：既存店と同一の数字を掛け算せず、席数、営業時間、客数、メニュー構成、立地の違いを入力してシナリオを比較する。

## 第3段階：経営判断の検証

- セット別の付帯率に加えて粗利額・値引き後の粗利・客単価への寄与を見る。昼夜の弱い時間帯だけで小さな施策を試す。
- 半玉の廃止は杯数の少なさだけで決めない。客層、再来店、廃棄、提供時間、粗利を比較する。
- 博多系とえび塩系の比率を曜日・昼夜・店舗で比較し、欠品やキャンペーンの期間を除いて仕込み配分を決める。
- チャーシュー丼単品とセット内の丼を区別する。セット構成が変わった場合は当時のレシピで換算する。
- 販促は実施前後の客数、客単価、値引き・広告費、粗利を揃えて比較する。

## 公開ゲート

機能完成 → 自動テスト → 店舗別の実機確認 → 売上・在庫の照合 → オーナー確認 → 本番表示。
本番データを変更するテストは事前に手順と対象を確定する。
