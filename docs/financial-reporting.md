# 経営分析・会計データの設計

## 集計単位

- 店舗 ID と営業日を必ず保持する。別事業体を単純合算せず、店舗ごとの分析を基本にする。
- 日次・月次は `pl-api`、年間・複数年は `financial-report-api` と `management_financial_months` を使う。10 年分でも最大 120 行の月次結果を返す。元注文数に比例する大きな JSON を画面へ渡さない。
- 売上は会計済みかつ非取消の注文を営業日で集計する。来店組数・客数は同一営業日の会計グループで重複を除き、グループがない注文は個別の組として扱う。売上増減は組数と1組あたり売上に分けて確認できる。注文時点と決済時点のずれ、後日取消・返金は今後の会計処理で個別に扱う。
- 販売手数料は現行ルールによる概算で、過去条件の変更履歴はまだ反映しない。月次 COGS は `order_items.quantity × products.cost_price` の**現在単価**を使う参考値。過去の原価スナップショットではない。正式な売上原価は仕入・期首期末棚卸・在庫移動と照合して別途確定する。
- 経費、人件費、販売手数料、廃棄、賄いを別系列で保持する。仕入原価と廃棄・賄いを二重計上しないよう、決算確定時に原価計算方法を定義する。
- 金額は現段階では税込である。課税売上の税率別内訳、仕入税額、非課税取引、適格請求書の要件、固定資産償却、未払・前払、銀行・現金照合は未実装。

## 追加できる分析軸

`management_financial_months` の月次 CTE に、新しい事実データ（客数、営業時間、人時、チャネル、天候、販促、商品原価スナップショットなど）を追加し、API の `summarize` と画面の表示を拡張する。元データ ID を失わず、定義・出典・計算期間を各指標に記録する。将来の大規模データでは月次確定スナップショットと再集計履歴を導入し、過去数字の変動理由を追跡する。

## 次回同月のシナリオ

同じ月の前年と対象年に会計済み注文がある場合のみ表示する。年間の前年比は完了月どうしに限定し、年内途中の累計を前年通年と比較しない。横ばいケースは対象年と同額、直線ケースは `max(0, 対象年 + (対象年 - 前年))`。営業日数、価格、季節イベントを補正した予測ではない。データが不足している月のゼロを実績のゼロと誤認しない。

## 税理士・決算向けに追加が必要なもの

1. 事業主体、会計期間、会計方針、税区分、勘定科目と取引先マスター。
2. 仕訳帳・総勘定元帳・貸借対照表を整合させる複式簿記、現金と銀行の照合、訂正履歴と確定処理。
3. 請求書・領収書の原データ、保存・検索・訂正履歴、インボイス番号検証、購入と経費・棚卸の紐付け。
4. 決算整理（棚卸、償却、未払・前払、売掛・買掛、納税）と税理士レビュー可能な明細出力。

現在の CSV は会計済み注文・経費・人件費参考値の追跡用であり、仕訳帳や法定帳簿の代替ではない。未入力件数は画面に表示し、確定を偽装しない。
