# 顔確認勤怠：試験運用

## 今回使える機能

- 登録済み店舗端末で顔から名前の候補を選択し、PINで本人確認する。すべての出退勤・休憩操作に既存のPIN認証を維持する。
- 読み取りは最大約3秒。初回モデル準備（最大12秒）、カメラ許可待ち（最大10秒）、サーバー通信（最大8秒）は別。名前選択・PINの経路は準備中から常に利用できる。
- PIN確認後、本人が説明に同意して3つの128次元特徴データを登録する。顔写真・動画は送信／保存しない。本人はPIN確認後に登録を削除できる。
- 顔確認開始時刻、候補、切替理由、PINで確認した本人と時刻をサーバーに保存。開始時刻だけでは本人や出勤を証明しない。給与用の打刻時刻は変更しない。
- 店長はスタッフ名簿から履歴画面へ進める。最新100件を表示。30日より古い履歴は次の顔確認開始で削除する。
- 通信の待ち時間に上限を設け、打刻保存成功後の状態再取得失敗を「打刻失敗」と表示しない。通信切断時は保存済みの可能性があるため、自動再送しない。

## 初回設定

1. 使用する店舗iPhone/iPadで店長ログインする。
2. スタッフ名簿で各スタッフの4〜8桁PINを設定する。
3. 「店舗打刻端末を開く」から店舗・端末名を登録する。端末登録後は店長トークンを削除する既存フローを維持。
4. スタッフが名前・PINで画面を開き、顔登録の説明に同意して登録する。明るい正面の位置で登録する。
5. 同じ店の端末で本人と別人、逆光・眼鏡・カメラ拒否を試す。名前を誤って選んだ場合は顔を再登録／手動選択する。

## まだ有効にしていない機能

- 顔だけでの自動打刻・ライブネス判定。顔照合単独では写真や映像による代理打刻を防ぎきれないため、今回の運用ではPINを必須とする。
- オフライン打刻の自動送信、通信断時の打刻時刻補正、給与計算ルールの変更。

## 保存・保護

`staff_face_templates` と `attendance_face_attempts` はRLS有効、anon/authenticatedの直接アクセス権なし。Edge Functionが登録端末・店舗所属・PINを検証する。保存特徴量も個人データとして扱う。従業員を退職処理する前に本人の顔登録を削除すること。ライブ照合の特徴量はDBやログに残さない。

## 依存物

face-api.js 0.22.2、upstream commit `a86f011d72124e5fb93e59d5c4ab98f699dd5c9c` のライブラリと3モデルを `vendor/face-api` へ同梱。ライセンスは同ディレクトリのMIT LICENSE。外部CDN呼出しは不要。顔確認にだけ約7.1MBを読み込み、注文画面には読み込まない。

## 検証

`node tests/attendance-face-match.mjs`、`node tests/attendance-face-models.mjs`。

DOMの操作検証はjsdomを別の作業ディレクトリにインストールし、`ATTENDANCE_TEST_MODULES=/absolute/path/to/node_modules node tests/attendance-kiosk-dom.mjs` を実行する。

`tests/attendance-kiosk.mjs` はPlaywrightでの実ブラウザ検証用。Playwrightと対応Chromiumが必要。本環境ではChromium配布物の取得に失敗しているため、iPhone/iPadでのカメラ精度・実ブラウザ検証は未完了。

`tests/attendance-face-api-smoke.mjs` は一時的なテストスタッフ／端末のみで実行する。実スタッフや実打刻を変更しない。テスト後に一時データを削除する。
