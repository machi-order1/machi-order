# V71 事業と店舗の境界

## 決定済みの前提

- V71 の飲食事業の運営者は個人事業。株式会社MACHIを運営会社として表示・割当しない。
- icoi、博多油そば151、BAR YANEURAは独立して移管できる事業として扱う。
- 151の長浜店と白木原店は、必要なら店舗単位でも切り離せる。
- 将来の法人化・事業譲渡は、発生日と移管範囲を記録する。過去の取引・勤怠・監査履歴を現在の所有者に読み替えない。
- MACHI ORDER は製品名であり、データ上の運営法人を意味しない。

## 現状とリスク

現在のデータでは151の `brands.company_id` が株式会社MACHIを指す。`staff_roster.company_id` と `inventory_items.company_id` も同社を共有し、`staff-admin-api` は会社単位でスタッフと店舗を読み出す。`staff_face_templates` はスタッフ単位の登録であり、独立した事業への移管境界を持たない。この状態でicoiを同じ会社の別店舗として追加すると、名簿・在庫・管理権限が混ざる。既存の会社IDを単純に置換すると、過去の記録の所属や参照権限も変わり得る。

## 目標モデル

| 対象 | 所属・移管の単位 |
| --- | --- |
| ブランド | 表示名・商標の単位。事業・店舗との関係を持ち、運営者の代わりに使わない |
| 事業 | icoi、151、YANEURAごとの安定したID。売却時の基本単位 |
| 店舗 | 一つの事業に属する安定したID。事業全体から独立した移管も可能 |
| 運営主体 | 個人事業または将来の法人。事業・店舗との関係は開始日と終了日で管理 |
| スタッフ | 人の識別と雇用・所属期間を分ける。賃金条件は適用期間を持たせる |
| 売上・勤怠・監査 | 店舗IDと、記録時点の運営主体を保存する。後の売却で過去記録を変更しない |
| 顔認証 | 店舗または事業の範囲で同意・登録・照合・削除を管理。譲渡先へ自動移管しない |
| 在庫・権限 | 店舗または事業に属させる。共用は明示した割当・移動・権限だけで扱う |

## 安全な導入順

1. 現在の151データ、会社単位の名簿・在庫、権限、過去の売上・勤怠を棚卸しする。
2. 運営主体と事業・店舗の期間付き関係を追加し、既存のIDを維持してデータを整える。過去の誤った会社ラベルの訂正は監査可能な手順で行う。
3. スタッフ管理、給与、在庫、顔認証の会社単位の参照を事業・店舗境界に変更し、他事業を参照・編集できないことを確認する。
4. icoiの店舗・スタッフを新しい境界に登録する。初回の実打刻前に管理者権限と記録先を実機で確認する。
5. 売却時は対象事業または店舗のエクスポート範囲を確定し、運営主体の期間を閉じ、譲渡先の権限を付与する。生体テンプレートは別途本人の同意を扱う。

この文書は設計案であり、DB変更や本番打刻の開始を意味しない。
