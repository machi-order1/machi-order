# 一杯ごとの具材調整・追加トッピング

この変更はTOPPINGS_TAKEOUT.mdの「トッピングを別商品として追加」を置き換える。

## お客様と厨房

- 白ネギ・青ネギ・キクラゲ・高菜：通常はこの商品の標準量。抜き0円／通常0円／大盛り100円を排他選択。通常はオプションなしとして扱い、既存カートや注文に選択を強制しない。
- 卵・チャーシュー等：追加トッピングとして任意選択。一杯のoption_idsへ保存する。追加料金を含めた単価をカートに表示。
- カートと厨房は既存order_item_optionsのスナップショットを、その油そばの行の下に表示。青ネギと白ネギを混同しない具材名を保存する。
- 同じ商品でも設定が違うものは自動統合しない。数量を増やすと同じ設定を複製する旨を画面で案内。
- 店内のトッピングカテゴリからも追加先のカート商品を選ぶ。数量2以上の行に追加する時は一杯を分離して追加し、残りを変更しない。同じ追加の二重課金を防ぐ。
- 注文済みの一杯への追加はスタッフに案内。過去注文の変更や返金は行わない。
- takeout.htmlでも同じ具材量・追加トッピング選択部品を使う。既存の持ち帰り単品商品は残し、油そば選択内の追加だけを一杯へ紐付ける。

## データとAPI

既存のoption_groups/options/product_option_groupsを拡張して、既存注文RPCをそのまま利用する。新しい注文APIや金額を信用するクライアント入力は追加しない。

- 各具材グループは任意・最大1つ。抜き0円、大盛り100円。通常は空配列。
- 生卵・半熟卵・炙りチャーシュー・激辛高菜・ローストビーフは追加トッピング。通常高菜の追加は高菜大盛り100円に統一して二重表示しない。
- options.source_product_idが元商品を参照。APIで商品・店舗売切状態を返し、UIで無効化。注文保存時にもトリガーで確認し、古いメニューからの注文を拒否。
- 元商品の基本価格を変更した時は、紐付いた追加料金を自動同期する。時間帯値引きはこの追加料金には適用しない。
- 新規トリガーはSECURITY INVOKER、固定search_path、PUBLIC実行権なし。新規公開テーブル、RLS変更、認証変更はない。

## 検証済み

`tests/customer-bowl-options.mjs`をPGlite 0.3.14の隔離DBで実行。SQL変更案と既存place_customer_order関数を実際に実行し、次を確認。

- 博多油そば「高菜抜き＋半熟卵」とえび塩「青ネギ抜き＋白ネギ大盛り」の保存先が別の注文商品行。
- 同じ油そばでも設定別に2行になる。全具材大盛りは一杯400円増、数量2で800円増。
- 必須麺量なし、不正な選択、同一具材の抜き＋大盛り、重複オプションを拒否。
- 元商品売切時は拒否し、注文全体をロールバック。
- カート2杯のうち1杯だけにトッピングを追加し、行を分離。再クリックの二重課金なし。
- トッピング価格同期、SQL再実行で重複なし、トリガー権限。
- 共通UIの通常へ戻す操作、排他選択、売切・選択数上限の検証。

これはローカルDBでの検証。実機表示、実店舗の厨房端末、決済の実取引は未検証。

## 統合・公開前の作業

本番DB・本番API・本番画面は未変更。DB変更案は`per-bowl-rollout.sql`に準備したが、**正式なmigrationにはまだなっていない**。この環境にはSupabase CLIがなく、CLI取得中にネットワーク承認処理がキャンセルされ利用できなかった。Supabaseスキルの規則に従い、手製のmigrationファイル名は作成していない。

1. 最新mainと管理側の変更を照合。今回はmenu-api、takeout-apiのGETレスポンスにも変更があるため、API担当の差分と特に照合する。POST処理・既存注文RPC・会計処理は不変。
2. CLIが利用できる環境で`supabase migration new per_bowl_customization`を実行し、生成したファイルへ検証済みSQLを移す。ステージングで既存履歴と共に適用して確認する。
3. DB → menu-api / takeout-api → customer-options.js・CSS・index.html・takeout.htmlの順に反映。DB列追加前に新APIを配信しない。
4. オプション件数・リンク対象・価格・売切・税込価格運用を確認。大盛りの実際の量は商品標準量と区別して店舗運用で定める。
5. 管理側とsw.jsのキャッシュ更新を一本化し、iPhoneと厨房・会計の検証を行う。

画面案bowl-customizer-fragment.htmlは2杯を切り替えて具材と追加料金を試すもの。厨房表示は保存データのイメージで、実際に注文は送信しない。
